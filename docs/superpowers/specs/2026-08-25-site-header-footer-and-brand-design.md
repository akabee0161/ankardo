# 共通ヘッダー/フッターとブランドアセット 設計

## 背景

段階①（カタログのアセット規約とメタデータ拡張）の完了時点で、サイトには次の欠落がある。

- `app/layout.tsx` に共通ヘッダー/フッターがなく、`/games` や `/games/<slug>` からトップへ戻る導線が存在しない。ブラウザの戻る操作以外に手段がない
- ファビコンがなく、タブでの識別ができない
- ロゴ/ワードマークがなく、サイト名はページ内のテキストにも現れない
- `metadata.title` が全ページ「Ankardo」で固定され、タブからページを区別できない

本ドキュメントは段階②の設計を定める。段階③（ジャンル絞り込み）は対象外。

## スコープ

**対象**: カタログサイト（このリポジトリの `site/`）のヘッダー、フッター、`/about` ページ、ブランドアセット（シンボル、ワードマーク、ファビコン）、ページタイトルのメタデータ。

**対象外**:

- プレイページ（`ankardo.com/play/<slug>/`）。各ゲームリポジトリの管轄であり、ゲーム側からカタログへ戻る導線は本段階では扱わない。ゲーム中はブラウザの戻る操作で復帰できるため、実害は小さいと判断した
- 既存ボタン（`bg-neutral-900`）の配色見直し（「未決事項」参照）
- OGP画像、SEO対策、アクセス解析の導入そのもの

## ブランドの由来

サイト名 Ankardo は、ナマズを地下で押さえるとされる要石の伝説に由来する。要石を英語にした anchor stone の「アンカー」の綴りを変え、接尾に do を付けたもの。ナマズはキーキャラクターとして今後も使う想定であるため、シンボルはナマズから引く。

錨（anchor）そのものを図案化する案は採らない。由来としては正しいが、記号としては海事を指してしまい、ナマズとも子供向けゲームとも接続しないため。

## シンボルマーク

ナマズを正面から見た顔。構成要素は次のとおり。

| 要素 | 内容 |
|---|---|
| 頭 | 横長の楕円（`rx=20` / `ry=14`）。ナマズの平たい頭を表す |
| 口 | 浅い「への字」。勾配を抑えて愛嬌のある表情にする |
| 目 | 白目（`r=3.4`）の内側に地色の黒目（`r=1.7`）。◎の内側を塗りつぶした形 |
| ヒゲ | 下向きに2本。上向きのヒゲは持たせない |
| 胸ビレ | 左右に1枚ずつ |
| 尾 | 付け根が太く先端が細いテーパー。三日月状に反り、先端に団扇型の尾ビレが軸上にまっすぐ付く |

## ワードマークと色

- ワードマークは「シンボル＋テキストの Ankardo」。テキストはシステムフォントの太字（`font-extrabold`）。Webフォントは読み込まない既存方針を継続する
- ブランド色は藍 `#1F3A5F`。`app/globals.css` の `@theme` に `--color-brand` として定義し、ジャンルカラーと同じ管理下に置く
- 適用先はヘッダー、フッター、ワードマークに限定する
- ヘッダーでは地（角丸四角）を敷かず、シンボルをそのまま置く。地を敷くとアプリのアイコンめいて重くなり、ワードマークとの並びが硬くなるため。地を敷くのはファビコンのみ

## ファビコン

- 白地の角丸四角に藍のナマズを載せる。地は不透明な白とし、タブやブックマークの背景色に左右されないようにする
- `app/icon.svg` を置く。Next.js のファイル規約により静的書き出しでも `<link rel="icon">` が生成される
- iOS のホーム画面用に `apple-icon.png`（180×180）を用意する。SVG からのラスタライズは ImageMagick の内蔵レンダラーが回転を含む図形を正しく描けるかを実装時に確認し、崩れる場合はヘッドレスブラウザで書き出す

透過（地なし）は採らない。暗いタブで藍が背景に沈み、輪郭が読み取れなくなるため。

## ヘッダーとフッターの構造

```text
app/layout.tsx           <SiteHeader /> {children} <SiteFooter />
components/SiteHeader.tsx    サーバーコンポーネント。640px以上はリンクを横並び
components/MobileNav.tsx     "use client"。640px未満のハンバーガーと全画面メニュー
components/SiteFooter.tsx    サーバーコンポーネント
lib/nav.ts                   リンク定義（パスとラベルの配列）
```

- ヘッダーは左にワードマーク、右にリンク。高さ56px、下辺に細い境界線。スクロール追従はしない。カタログの各ページは短く、常時56pxを占有する見返りが小さいため
- フッターはリンク3本（トップ／ゲーム一覧／このサイトについて）、コピーライト、サイト説明1行
- `body` を `flex min-h-screen flex-col` にし、フッターを常に最下部へ送る
- リンク定義を `lib/nav.ts` に集約し、ヘッダーとフッターで共有する。段階③でリンクが増えても変更が1ファイルに収まる。`lib/genres.ts` / `lib/devices.ts` と同じ既存パターン

## モバイルナビゲーション

640px（Tailwind の `sm`）未満でハンバーガーを表示し、開くと画面全体を覆うメニューを出す。リンクは大きな文字で縦に並べる。

ヘッダー直下に開くパネル型ではなく全画面型を選ぶ。現状のリンクは2本で全画面は過剰だが、段階③でジャンル絞り込みが入るとリンクが増える見込みであり、その時点で作り直さずに済むため（ユーザー判断。実装コストは許容する）。

`MobileNav` はこのサイト初のクライアントコンポーネントになる。次を実装する。

- 開閉状態の管理
- Esc キーで閉じる
- 開いている間は背後のページをスクロールさせない
- 閉じたときフォーカスをハンバーガーボタンへ戻す
- `aria-expanded` と `aria-controls` を付与する

## `/about` ページ

`app/about/page.tsx` の静的ページ。4ブロック構成。

**1. このサイトについて** — サイトの目的、想定する年齢層、ゲームの選び方（年齢・ジャンル・対応デバイスの見方）を保護者向けに説明する。

**2. 安全性の方針** — 次の3点を書く。いずれも現時点の事実に基づく。

- 広告・課金・アカウント登録はない
- ゲームの記録（ハイスコアなど）は端末内にのみ保存され、サーバーへは送られない（`rungame-sample` は `localStorage` にハイスコアを保存する。カタログ側に送信はない）
- アクセス解析を行う場合も、個人を特定しない集計のみで Cookie は使わない

3点目を将来を含む書き方にするのは、アクセス解析を今後導入する意向があるため。「解析は行っていない」と断定すると導入時に虚偽になる。この文言は同時に制約でもあり、**Cookie や識別子で利用者を追跡する解析ツール（GA4 等）を入れるなら、導入時に about を書き換える必要がある**。Cookie を使わない集計（Cloudflare Web Analytics 等）であれば書き換えは不要。

**3. 掲載しているゲームについて** — 掲載しているゲームはすべて運営者本人の制作であることを書く。

**4. 運営者と連絡先** — 運営者を GitHub アカウントへのリンクで示し、連絡手段として Google フォームへのリンクを置く。メールアドレスは公開しない。GitHub Issue を主たる連絡手段にはしない（一般の保護者が使う手段ではないため）。

## メタデータ

- `metadata.title` に `template`（`%s | Ankardo`）と `default`（`Ankardo`）を設定し、各ページで `title` を指定する
- 詳細ページはゲーム名を `title` にする

## テスト方針

既存方針「表示コンポーネントにはテストを書かない（ロジックを持たず、JSXがそのまま出るだけのため）」を維持する。`SiteHeader` / `SiteFooter` / `/about` はこれに該当し、テストを書かない。

`MobileNav` は例外とし、テストを書く。実際の振る舞い（開閉、Esc、フォーカスの戻り先、`aria-expanded`）を持つため。Vitest の実行環境は現在 `node` なので、`jsdom` と `@testing-library/react` を追加し、この1ファイルのみ `jsdom` 環境で実行する。

## 未決事項

- **既存ボタン（`bg-neutral-900`）の配色**。ブランド色を藍にしたことで、ボタンの黒との関係が未整理になる。藍に寄せるか黒のまま据え置くかは本段階では決めず、ボタンは黒のまま据え置く。全ページの再確認が必要になり、段階②のスコープを超えるため
- **アクセス解析の導入**。ツール選定と実装は別段階。上記「安全性の方針」の文言が制約になる
- **OGP画像、SEO対策**。長期バックログのまま
